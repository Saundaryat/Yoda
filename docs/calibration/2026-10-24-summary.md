# Clinic evaluator calibration — 24 October 2026

## Protocol and labels

For each of the 20 scenarios, authored one correct trace and one deliberately incorrect trace.
CRM tool calls were executed against the real mock CRM, retaining accepted and rejected results.
Expected outcomes and the particular checks expected to fail were fixed before judge calls and
not supplied to the judge. These are agent-authored labels, not an independent human panel.

The final evaluation used the production Claude Sonnet 5.5 judge and Jev 1.14.0 severity
classifier on all 40 reference traces plus eight prewritten correct wording variants.
The deterministic tests separately check all 40 traces using the reference labels as a judge
stub; those unit tests do not establish model accuracy.

## Findings and corrections

- A booking-note case required a second consent despite an opening authorizing the exact
  service/time if free. Removed the redundant confirmation requirement. Other explicit-consent
  and slot-recovery cases still require consent before the relevant booking.
- The same-day case did not identify a service, yet required a cleaning booking. The opening
  now asks for a cleaning, eliminating a hidden expectation.
- A safe guardian refusal could be interpreted as failing a question phrased “before booking.”
  Clarified that guardian instructions plus no booking pass, without requiring identity tools.
- Service recall was optional enough to permit a memory failure to pass on aggregate score.
  It is now critical for that scenario's stated objective.
- A structured note could have any date and still pass its regex. Added a comparison against
  the successful booking's actual service, date and clinic-local time.
- The judge silently accepted missing or duplicate reply/task judgments. It now rejects these
  as evaluator/provider errors for retry rather than issuing a partial score.
- The judge could hide decisive tool data after 800 characters. Full tool results are rendered.
- The first live calibration matched 39/40 cases; the note-date negative exposed quote validation
  that searched only SMS text. The corrected verifier and evidence linker include actual tool
  arguments/results. The failed first report is retained rather than overwritten.
- A report with zero judged agent replies no longer receives a clean grounding pass.
- Session boundaries no longer claim every session is the same contact; contact-isolation
  scenarios deliberately use two customers. Session-scoped questions state their scope.

## Observed calibration results

- First live pass: 39/40 matched, one evaluator error; estimated cost $0.487553268 (plus any
  unreported provider cost for the failed/retried request).
- Final live pass: 48/48 matched: all 28 correct/wording traces passed, and all 20 incorrect traces
  failed with the intended failure checks. Estimated cost $0.58380205.
- Separate Jev boundaries: 6/6 labels matched: false booking, price, callback deadline and time
  were serious; a casual signoff and cosmetic descriptor were minor. Probabilities are retained
  in the severity report; confidence is not treated as calibrated statistical certainty.

See `2026-10-24-pass1.json`, `2026-10-24-final.json`, and `2026-10-24-severity.json` for the actual
traces, model outputs, tool state and costs. The suite manifest pins task hashes and evaluator
source hashes before the real A/B experiment. No existing experiment is automatically rescored.

## Limits

These small synthetic fixtures exercise known boundaries. Agreement here does not prove
accuracy on unseen conversations. Related clinic cases share policies and tools, so a result
on the 20 scenarios is conditional on this suite, not a population estimate across businesses.
The real run uses three repetitions to expose variability; an inconclusive result remains a
valid outcome. Do not change fixtures or rubrics after seeing that experiment to create a winner.
