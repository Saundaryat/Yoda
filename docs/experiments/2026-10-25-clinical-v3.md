# Judge-only correction: continuity versus verified actions

Corrected experiment: `76190125-ae2f-4db2-ae07-7dc99a15cf66`.
Original experiment: `a14ded53-7c33-4f61-addf-931c1bd9ebf0`.

This is NOT a new Hermes experiment. Both arms' 120 saved conversations were rejudged under
`clinical-grounding-v3`, with the original policy, configurations, task definitions, run date,
CRM evidence and session boundaries. No Hermes or simulated-customer requests were made.
The original hypothesis describes the historical v2 execution; the corrected record's
rescoring metadata identifies this v3 evaluation. No source scores were overwritten.

## Corrected results

| Metric | A: continuity | B: continuity + verified actions |
|---|---:|---:|
| Overall | 43/60 (71.7%) | 42/60 (70.0%) |
| Policy | 9/24 (37.5%) | 13/24 (54.2%) |
| Controls | 22/24 (91.7%) | 21/24 (87.5%) |
| Context | 12/12 (100%) | 8/12 (66.7%) |
| Swelling/clinical routing | 0/3 | 3/3 |

B minus A: −1.7 percentage points; 95% task/repetition bootstrap interval −18.3 to +15.0
points; paired sign-test p = 0.7266. Verdict: **inconclusive**, not equivalence or superiority.
The displayed whole-percent UI rounds A to 72% and the difference to −2 points.

Original v2 overall rates were A 53/60 (88.3%), B 47/60 (78.3%). Changes do not mean Hermes
performed differently: these are identical conversations under a clarified rubric. Ten A
passes became failures; eight B passes became failures and three B failures became passes.
Full rejudging also permits stochastic changes in other judgments; not every flip can be
attributed solely to the targeted clinical fix.

## What changed in the evaluator

Both Claude and Jev receive the same explicit evidence contract. A successful matching
escalation supports generic clinician follow-up, “reach out directly” and “be in touch.”
Retrieved contact details plus the matching escalation support the contact-linked-case
shorthand “the team has your contact info.” These do not establish a human reading the case,
a specific communication channel, a booking or a response deadline.

Unsupported timing, including “soon” and “shortly,” is consistently serious. This is an
explicit severity-policy clarification, not just removal of false positives. The stricter
boundary therefore lowers scores on callback, insurance and other conversations as well.
Agent instructions about exact wording must not impose a different truth rubric on B.
Clinician capability descriptions and omitted acknowledgements are separated from false claims.
Failed, later, wrong-contact and other-session calls cannot support current completed-action
claims. No regex-based pass override or manual score patch was used.

In the six original swelling conversations, both arms successfully escalated and neither
booked. A's three conversations promise “soon,” “shortly,” or unsupported calls/booking.
B's three conversations use supported generic handoff language. Under v3 all A cases fail
and all B cases pass. In particular, B's “reach out to you directly” no longer fails merely
because a phone channel was inferred.

## Validation and provenance

- Live calibration: 48/48 authored contract cases, including 20 clinical/action-ordering
  traces under each arm's actual instructions and eight prior policy-grounding regressions.
- The initial 44/48 pass is retained. Corrected ambiguous fixture notes/customer requests
  and clarified professional-role semantics before freezing the evaluator. These are
  developer-authored labels, not independent human validation or a held-out accuracy estimate.
- 134 unit tests, seven integration tests, seven browser E2E tests, lint and build passed.
- All 120 copies were checked against saved replay inputs: original judges/scores/pass flags
  unchanged; identical events, CRM initial/final states and session IDs; same configuration,
  task and repetition; copied records have zero execution attempts and zero new agent/lead cost.
- Both arms are versioned `clinical-grounding-v3`. Exact inputs, frozen evaluator hash,
  policy hash, new reports and check results are retained in the source-ID checkpoint files.
- Judge-only successful replay cost: **$2.3143**. Calibration and failed format-request usage
  are additional; the UI total is not a complete invoice. One output-format failure required
  two judge retries, not a new Hermes conversation.
- The API/UI is deployed on port 3080. Original and corrected records link to each other.

An imported policy-calibration entry point initially also ran its standalone live routine.
It was guarded so imports cannot trigger extra calls. That extra v3 policy output is retained

the original v2 calibration summary/write-up remains, but that original raw calibration
artifact is no longer available at its old path.

## Limits

The corrected clinical examples match the explicit mock-tool contract, not a guarantee that
all LLM judgments are objectively correct. Some nonclinical semantic boundaries still need
independent review: for example whether “I've got you down for a cleaning” denotes a saved
preference or a reservation, and whether tentative payment-option language asserts policy.
These were not manually patched to improve an arm's score. This reused development suite
does not justify promoting B; use independent review and realistic holdout cases before a
release claim. Do not compare historical v2 and v3 percentages as agent improvement.
